## 3. ⚠ 指示書§4「血統登録番号を主キーとする」は現データで実装不能

| 側 | 血統登録番号 |
|---|---|
| 調教・ウッド週次CSV(40列) | **あり**(31列目、1,127/1,127 = 100%) |
| 調教・坂路週次CSV(18列) | **無し** |
| 結果・netkeiba JSON | **無し**(`horse_id` はある) |
| 結果・JRA公式CSV | **無し** |

**結果側のどちらにも血統登録番号が無い**ため、両側を血統登録番号で突き合わせることはできない。
結合できた1,851頭のうち血統登録番号が取れたのは **642頭**(最終追切がウッドだった馬のみ)で、
これは調教側だけの値であり結合キーには使えていない。

したがって本監査の結合は **(馬名, 競走日, 競走ID)** による暫定である。曖昧さは次のとおり定量した。

- 同一の本追切窓に**同名の馬が複数行**存在したケース: **15件**(`duplicate_audit.csv`)
- 1,851頭に対して 15件 = 0.8%。無視できないが支配的でもない

**未来情報混入の防止**は実装済み: 本追切窓を「競走日直前の月〜金」に限定し、
`調教日 < 競走日` を全レコードで表明(assert)している。最終追切・1週前追切・その他追切は別列で保持。

### 「9開催日1,667頭と12開催日1,845頭の関係」

別の集合ではなく、**包含関係**である。

```
JRA公式結果CSV        9開催日 1,667頭   … data/results/official_results_20260712-20260809.csv
  ＋ netkeiba JSON    3開催日 1,419頭   … 8/16(490) + 8/22(471) + 8/23(458)
  ────────────────────────────────
  結果レコード合計   12開催日 3,086頭
  − 取消・中止・除外              31頭
  ────────────────────────────────
  出走(COMPLETED)              3,055頭
  − 本追切が窓内に無い         1,204頭
  ────────────────────────────────
  結合成功                     1,851頭   ← 第6報の「1,845頭」
```

第6報の 1,845 と本監査の 1,851 の差 **6頭**は、本監査が
「同日複数追切のとき最も遅い時刻を採る」規則を明示したのに対し、
第6報が「最長距離を優先」していたことによる。**本監査の1,851を正とする。**
