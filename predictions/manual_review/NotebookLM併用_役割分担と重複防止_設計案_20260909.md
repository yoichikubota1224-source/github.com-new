## 0. 結論

**この方向には賛成です。** NotebookLM併用は、当方が9/7の独立レビューで **M-1「独立起動本数の縮約リスク」** として挙げた問題に対する、**最も直接的な打ち手**です(§2)。

ただし、**先に片づけないと逆効果になる衝突が1つあります。**

> **当方の固定指示には「旧NotebookLMの『資料保管・根拠確認』役を引き継ぐ」と明記されています。**
> NotebookLMがその役に戻るなら、**同じ役を2つの主体が持つ**ことになります。
> 役割を再定義しないまま併用すると、「深堀」ではなく**同じ作業の二重化**になり、
> しかも**両者が一致したときに「2つが同意した」と読んでしまう**——これは
> 二重加点そのものです。**§1に3案を用意しました。裁定をお願いします。**

あわせて、**「精度向上」の測り方**に注意点が1つあります(§6)。数レース/週では、**短期の的中で改善を判定できません**。工程の被覆で測る設計にしてあります。

## 2. なぜこの方向に賛成なのか — M-1への答えになる

9/7の独立レビューで、当方は **M-1** として次を指摘しました。

> 8月のクロス方式の中核は「**独立に評価する主体が複数あり、互いの結論を入力にしない**」こと。統一運用案の「観点を残しつつ少数工程へまとめる」方向は、**観点の保存**と**独立起動の本数**を同一視すると、単一経路の見落としを検出する手段そのものを失う。

**NotebookLM併用は、独立起動の本数を実際に増やします。** しかも当方の「13視点」より意味のある形でです。

| | 13視点(8/16の方式) | NotebookLM併用 |
|---|---|---|
| 入力 | **同一**の出馬表CSV・同一の指数 | **別**(PDF/docx等、NotebookLM側の投入資料) |
| 実行系 | **同一モデル**の中の13の観点 | **別システム** |
| 独立性 | 観点は分かれるが、**同じ入力を同じモデルが読む**ため、入力の欠陥や読み違いは13視点すべてに同じように伝播する | **入力も実行系も別**。一方の読み違いがもう一方に伝播しない |

→ **13視点の一致は「独立な13票」ではありません。NotebookLMとの一致は、それに近いものになり得ます。** ここが今回の変更の本質的な価値です。

**ただし条件があります。それが§3です。**

## 3. 一致を価値にする唯一の条件 — ブラインド

**両者が互いの結論を見てから答えると、一致は何も意味しません。** 後から見た側が引きずられるためです。

```text
必須の順序(どの案でも共通)
1. 同じ一次入力(出馬表・指数・調教CSV等)を、両者へ同時に渡す
2. 互いの結論を渡さない状態で、それぞれが出力する
3. 出力が両方揃ってから、突き合わせる
```

- **NotebookLMへ、Claudeの出力(適性・限定判定語・展開)を投入しない。**
- **Claudeへ、NotebookLMの結論を「入力」として渡さない。** 突合の段階で渡すのは可です。
- 順序が崩れた回は、**`BLIND=NO` と記録**して、その回の一致を根拠に使わない。

### 3-1. 突合結果の扱い

| 結果 | 扱い | 理由 |
|---|---|---|
| **一致** | **二重加点しない。** 「1つの根拠が2度確認された」と記録する | 展開係v3案 §3-7 禁止事項#8。同じ一次資料に基づく一致は、独立な2票ではない |
| **不一致** | **人間確認必須へ上げる。** どちらが正しいかをAI同士で決めない | ここが最も価値のある出力。**不一致こそが探しているもの** |
| **片方のみ言及** | **[不足]として記録。** もう一方が「無い」と言ったのか「見ていない」のかを区別する | 沈黙を否定と読まない |
| **両方が不明** | **[不足]** | 推測で埋めない |

> **不一致の件数は、この併用が機能している証拠です。** 一致ばかりなら、独立になっていない可能性を疑ってください。

## 4. 「数レース特化」のスコープ定義

**選定ゲートを先に通し、その後で深堀対象を決めます。** 順序を逆にすると「深堀したいレースを選ぶ」ことになり、選定基準が後付けで緩みます(9/7レビュー R-1 と同じ機序)。

```text
手順
1. 全Rの機械点検(欠損・取消・障害・新馬・頭数)
2. 荒れ選定ゲート(テクニカル6のP判定＋妙味密度)で候補を出す
   → 0Rでも正常。選定数を成果指標にしない
3. 候補の中から、深堀対象を「数レース」に絞る
   → 絞り込みの基準を事前に固定し、絞った後で基準を変えない
4. 対象外にしたレースも一覧に残す(理由コード付き)
```

**「数レース」の本数は羊一様の裁定事項**です。参考として、8/16の実績では **P1〜P3の波乱側が13R、妙味密度2頭以上に絞って5R** でした。深堀の工数を考えると **3〜5R** が現実的と見ますが、**当方が決めるべきことではありません**。

**対象外レースの記録を必ず残してください。** 深堀していないレースが荒れた場合、「選定が悪かったのか、深堀していなかっただけか」を後から区別できなくなります。

## 5. 「抜け漏れ防止」を測れる形にする

「抜け漏れがない」を印象で言わないための、**機械的に検査できる定義**です。

| # | 検査項目 | 合格条件 | 不合格時 |
|---|---|---|---|
| N-1 | **全頭被覆** | 出走表の頭数 = 分析表の行数。取消・除外は状態を別記 | **人間確認必須**。欠落馬番を明記 |
| N-2 | **判定列の適用母集団** | 判定系の列が、対象全頭に付いている(選定後に付与しない) | 空欄を「該当なし」と読まない。`NO(理由コード)` を明示 |
| N-3 | **穴帯の無言除外0** | 7〜12人気の全頭が、いずれかの行に現れる | 落ちた馬番と理由を記録 |
| N-4 | **[不足]の保持** | 未取得が0や「なし」に変換されていない | 変換箇所を差し戻す |
| N-5 | **ビューの部分集合明示** | 抜粋表に `原本件数 / 掲載件数 / 除外条件` が併記されている | ビュー単独で母集団を判断しない |
| N-6 | **ブラインド成立** | 両者の出力時刻が、突合開始より前 | `BLIND=NO` を記録し、その回の一致を根拠にしない |

> **N-1〜N-3 は、8/16に実際に破れていた項目です**(`fatal_flags` 非空 0/478、`hole_axis_eligibility` は穴帯191頭中21頭のみ、妙味グレード付き原本37頭に対しビュー掲載11頭)。**併用の有無に関わらず、ここが最大の抜け漏れ源**です。

## 6. 【注意】「精度向上」の測り方

ご指示の目的に「精度向上」がありますが、**数レース/週では短期の的中で改善を判定できません**。

- 週3〜5Rなら、**1ヶ月で12〜20R**。3着内率の差を検出するには全く足りません。
- `ACCURACY_SCORING=NO` が維持されている以上、**的中で方法の当否を決めない**のが現行の建て付けです。
- 9/8の測定でも、n=283 で **差の95%CI が [−4.6, +7.3]pt** と判定不能でした。数レース/週はそれよりはるかに小さい標本です。

**したがって、当面は「工程の被覆」で測ることをご提案します。**

| 測る対象 | 指標 | 判定できる時期 |
|---|---|---|
| 抜け漏れ防止 | **N-1〜N-6 の合格率** | **1週目から**。二値で明確 |
| 深堀 | 不一致の検出件数／[不足]の解消件数 | 1週目から |
| 独立性 | `BLIND=YES` の回の割合 | 1週目から |
| **精度向上** | 3着内率・回収率 | **判定しない**(標本不足)。記録のみ蓄積 |

**「今週から良くなった」と言えるのは被覆の方だけです。** 的中は記録に留め、判定は標本が貯まってから、別期間ホールドアウトで行ってください。

## 7. 記録様式(最小限)

後から効果を測れるように、毎回これだけは残してください。

```text
run_id / 対象日 / 対象レースキー(深堀した分・しなかった分の両方)
情報締切時刻 / 入力ファイル名とhash / 参照TBの版
BLIND = YES / NO
NotebookLM側の出力(出典付き) と Claude側の出力 を別ファイルで保存
突合結果: 一致n件 / 不一致n件 / 片方のみn件 / 両方不明n件
N-1〜N-6 の合否
人間確認必須へ上げた項目
```

**事前版を上書きしないでください。** 結果を見た後に事前分析を直すと、何が予測で何が後知恵か区別できなくなります(展開係v3案 §3-4 と同じ)。

## 8. 当方の出力の変更点

どの案でも、当方の出力は現行のまま変わりません。

- 買い目・馬番の組合せ・点数・資金配分・最終印・最終採用馬・購入可否・精度採点は**出しません**
- 結論は**限定判定語**で渡します(本体で本採用再判定／保留論点あり／断念疑い／軸不可疑い／ワイド穴として照合／薄め相手として照合／人間確認必須)
- 適性A/B/C・信頼度A〜D。**馬券印に見える記号は生成しません**
- **NotebookLMとの一致を、当方の確度を上げる根拠に使いません**(§3-1)
