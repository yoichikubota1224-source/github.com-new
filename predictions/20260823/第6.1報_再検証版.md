## 4. §4 血統登録番号キーが実装不能である理由[実]

| 側 | 血統登録番号 |
|---|---|
| 調教・ウッド(40列) | **あり**(100%) |
| 調教・坂路(18列) | **無し** |
| 結果・netkeiba JSON | **無し**(`horse_id` はある) |
| 結果・JRA公式CSV | **無し** |

**結果側のどちらにも無い。** よって両側の突き合わせに使えない。
現状は **(馬名, 競走日, 競走ID)** による暫定結合であり、曖昧さは
「同一の本追切窓に同名馬が複数」**15件 / 1,851頭 = 0.8%**(`duplicate_audit.csv`)。

**未来情報混入は防止済み**: 本追切窓を競走日直前の月〜金に限定し、全レコードで `調教日 < 競走日` を表明。
最終追切・1週前追切・その他追切は別列で保持。

添付が届けば、調教側は血統登録番号で統一できる。**結果側にも血統登録番号を持つソース**
(JV-Data の SE/RA レコード等)が必要である。
