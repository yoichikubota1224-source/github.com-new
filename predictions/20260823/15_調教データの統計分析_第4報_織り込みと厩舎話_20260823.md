## 1. 「半比例」の検証 — 良い調教は織り込み済み、悪い調教は織り込まれていない

単勝回収率は「勝率 × 勝った時の平均配当」に分解できる。
調教が勝率を上げても回収率が上がらないなら、その分オッズが短くなっている＝**市場が織り込んでいる**。

| 人気帯 | 調教順位 | n | 勝率 | 勝時平均配当 | 単回収 | 勝率比 | 回収比 |
|---|---|---:|---:|---:|---:|---:|---:|
| 1〜3人気 | 上位1/3 | 150 | 22.7% | 3.5倍 | 78.7% | 1.00x | 1.00x |
| | 中位1/3 | 53 | 22.6% | 3.6倍 | 81.3% | 1.00x | 1.03x |
| 4〜6人気 | 上位1/3 | 87 | 11.5% | 10.7倍 | 123.4% | 1.00x | 1.00x |
| | 中位1/3 | 68 | 5.9% | 12.1倍 | 71.3% | 0.51x | 0.58x |
| | 下位1/3 | 55 | 5.5% | 13.7倍 | 74.7% | 0.47x | 0.61x |
| 7〜12人気 | 上位1/3 | 19 | 5.3% | 20.3倍 | 106.8% | 1.00x | 1.00x |
| | 中位1/3 | 142 | **1.4%** | **63.5倍** | **89.5%** | **0.27x** | **0.84x** |
| | 下位1/3 | 208 | 1.0% | 40.1倍 | 38.6% | 0.18x | 0.36x |

### 読み方

**1〜3人気帯**: 調教順位で勝率がまったく分かれない(22.7% vs 22.6%)。回収率も78.7%と81.3%で横並び。
**7〜12人気帯の中位1/3**: 勝率は上位の**0.27倍**しかないのに、回収率は**0.84倍**まで戻る。配当が20.3倍→63.5倍と3倍になって埋めている。

**これが羊一様の見立ての正体である。良い調教を買っても回収率は上がらない。既に値段がついているからである。**

### ⚠ ただし下振れ側は埋まっていない

| 母集団 | n | 単回収 | ブートストラップ95%CI |
|---|---:|---:|---|
| 調教指数 **下位1/3** | 325 | **37.3%** | **[5.6, 82.2]** |
| 同(4人気以下) | 321 | 37.8% | [5.7, 82.6] |
| 同(8/22のみ) | 164 | 20.0% | [0.0, 51.1] |
| 下位1/3以外 | 593 | 88.9% | [53.5, 134.2] |

**下位1/3だけ、信頼区間が100%を含まない。** 8/22単日でも同じ。

しかも**頑健性の向きが逆**である。勝ち馬は325頭中5頭しかなく、配当上位を抜くと 37.3% → 20.8% → 12.7% と**さらに下がる**。
これまで見てきた高回収率の主張は配当1本で崩れたが、低回収率の主張は配当を抜くほど強まる。

**これは調教分析全体で、統計的に生き残った唯一の回収率の主張である。**

### 理論(第4稿) — 第3報を更新する

> **調教の「良い」情報は市場に織り込まれている。だから回収率には効かない。**
> **織り込まれていないのは「悪い」情報のほうで、超過情報はそこにしかない。**

線形の反比例ではなく、**上振れ側は裁定され尽くし、下振れ側は残っている**という非対称である。
第3報の「調教は下振れ検出器」と、羊一様の「半比例」は、同じ現象の別の見方だった。

機序は「良い調教が悪い」のではなく「**良い調教は既に値段がついている**」である。

⚠ 標本は2開催日。回収率の信頼区間は依然として広い。`RULE_PROMOTION: NONE`。

## 2. 厩舎話 — 競馬ブックからの機械取得は行わない

### 2-1. 一次情報で確認した事実

**`p.keibabook.co.jp` と `s.keibabook.co.jp` の robots.txt は、両方とも次の内容だった**[実・自分で取得]。

```
User-agent: *
Disallow: /
User-agent: Googlebot
Disallow: /chihou/
Disallow: /news/
```

**全クローラに対する全面 Disallow。** 例外はGooglebotのみである。
調査エージェントは加えて、利用規約に「本サービスは閲覧を目的としていますので、**プログラムでのデータ取り込み**や、他のお客様にご迷惑のかかるご利用方法は禁止します」「個人的な利用の範囲を超え…無断で転載・複写・**蓄積**又は転送することは禁止」との記載があり、違反時は退会を求める旨があると報告した。

### 2-2. 判断

**競馬ブックからの厩舎話の機械取得は行わない。**

理由は予測力の見込みではない。**robots.txt が明示的に拒否しており、規約がプログラムでの取り込みと蓄積を名指しで禁じているため**である。
これは設計の工夫で回避すべき制約ではない。羊一様がご自身で読まれる分には規約が明示的に許諾しているが、**私が自動で取り込むことはしない**。

なお調査の過程でエージェントが構造確認のため1ページを取得した。継続的な取得は行っていない。

### 2-3. カバレッジの問題(仮に規約が解決しても残る)

| 項目 | 実測 |
|---|---|
| 無料〜Smartプレミアム | 厩舎の話は**3頭のみ表示**(馬番1・2・3) |
| 全頭取得 | webライト(月1,100円)以上が必要 |
| 提供時刻 | 前日11時以降 → **日曜レース分は土曜11時で、金曜締切に間に合わない** |

馬番1〜3固定は人気順でもランダムでもない**非ランダム選抜**であり、この形では統計に使えない。

### 2-4. 先行知見 — 予測力の証拠は「無い」

**厩舎コメントが着順・回収率を予測するかを定量測定した研究・記事は、日本語・英語のいずれの検索でも1件も発見できなかった**[不足]。

これは「効果なし」の証拠ではなく「**未測定**」である。両者を混同してはならない。
日本語圏のヒットは全て定性記事で、勝率・複勝率・回収率・標本数・有意性を伴うものはゼロだった。

⚠ 調査で見つかった2025年のLLMセンチメント論文(回収率279%)は、**試合後コメントを特徴量にしており事前予測として成立しない**(ルックアヘッド・リーク)。この種の数値を根拠に使ってはならない。

### 2-5. 供給側の性質 — テキスト特徴量に不利な事実

- **競馬ブック自身が、調教短評の社内基準は統一されていないと公言している**。公式コラム原文: 短評は「600種類以上」、「時計班数名が手分けして」各自入力、「決して社内きっちりと統一されているわけではない」 → **強い記者固定効果が乗る**
- **厩舎の話の話者が混在している**(調教師・助手が混在)
- **同一ベンダーが同一締切で数値要約を併売している**。厩舎の話と同じ「前日11時以降」に、本紙予想印・AI指数・短評・攻め解説が配信される。**同じ取材網が同じコメントを読んで作った要約が、同時に市場へ出る**

§1で確認したとおり、公開情報の「良い」側は市場に織り込まれる。厩舎話も同じ経路をたどる可能性が高い。

## 3. ⚠ 方針を変えるべき発見 — JRDB CHA に[不足]項目が揃っている

第1〜3報で**3回にわたり[不足]と報告してきた項目**が、既に契約系列にあるベンダーの別データに**構造化済みで存在する**ことが分かった。

**JRDB「調教本追切データ(CHA)」の仕様書を一次情報で確認した**[実・自分で取得: `http://www.jrdb.com/program/Cha/cha_doc.txt`]。

| 第1〜3報で[不足]としていた項目 | CHAでの提供 |
|---|---|
| **併走 / 単走** | `併せ馬相手データ`。**※3「併せ馬が無い場合、相手不明の場合は、スペース」→ 単走が判別できる** |
| **先着 / 遅れ** | `併せ結果` 1:先着, 2:同入, 3:遅れ |
| **馬なり / 一杯** | `追切種類` 1:一杯, 2:強目, 3:馬なり |
| **相手馬の格** | 相手の`年齢`・`クラス`(競走条件コード) |
| 乗り役 | 1:助手, 2:調教師, 3:本番騎手, 4:調教騎手, 5:見習 |
| 調教時の馬場状態 | **※2「指数は、当日の馬場差、通った位置で補正されています」** |
| 最終追切の特定 | **※1「レース前の水曜、木曜いづれかの調教で、併せ馬、時計、距離、調教の強さ等を考慮して選択した調教」** |

さらに時計は `テンＦ / 中間Ｆ / 終いＦ` と、それぞれの**指数**、および `追切指数` が入っている。

### これが重要な理由

**第3報の理論は「価値は時計ではなく文脈にある」だった。CHAの指数は、仕様書の記載どおり当日の馬場差と通った位置で補正済みである — 構造上すでに文脈化されている。**
第2報で私が苦労して定義した「最終追切 = D-2以前で最新」というルールも、CHAでは※1でベンダー側が本追切を特定しており不要になる。

| 項目 | 内容 |
|---|---|
| ファイル形式 | 固定長テキスト(CP932)、レコード長64バイト |
| 更新 | 金曜20:00頃 / 土曜20:00頃 |
| 提供 | 開発者向け仕様書が公開されており、機械可読の取り込みが前提の設計 |
| robots.txt | `www.jrdb.com` の Disallow は `/_mm/ /_notes/ /_baks/ /MMWIP/` のみ。仕様書パスは対象外 |
| 仕様書の保存先 | 本リポジトリ `docs/jrdb_cha_doc_utf8.txt`(UTF-8変換版) / `docs/jrdb_cha_doc_cp932.txt`(取得原本) |

### ⚠ 契約状態は未確認

**現在のJRDB契約(IDMを取得している)に CHA が含まれるかは[不足]。** 入会案内ページに明記が無く、契約前の確認が必要である。
JRDB全体の利用規約は「私的に競馬予想」する利用を許諾し再配布を禁じる、と調査エージェントが報告しているが、**私は一次確認していない**。

## 4. 推奨

### やらないこと

**競馬ブックからの厩舎話の機械取得。** robots.txt が全面拒否しており、規約がプログラム取り込みと蓄積を禁じている。設計の改良で解ける制約ではない。

### 先にやるべきこと

**JRDB CHA の契約可否を確認し、取得できるなら第5報でこれを検証する。**

理由:

1. **第1〜3報で[不足]としてきた項目(併走/単走・先着/遅れ・馬なり/一杯・相手の格・馬場差補正)がすべて揃っている**
2. **既に契約系列にあるベンダー**であり、機械可読の取り込みが前提の設計になっている
3. **過去分が即座に取れる**ため、開催日を待たずに標本を積める
4. **第3報の理論が予測する方向**と一致する。時計ではなく文脈の情報である

**厩舎話の是非は、CHAを回した後にしか正しく評価できない。** CHAで文脈情報の予測力が測れれば、「自由文でしか取れない残りの情報」がどれだけあるかが初めて分かる。

### 検証の順序(提案)

| 段階 | 内容 | 前提 |
|---|---|---|
| 1 | CHA契約可否の確認 | 羊一様のご判断 |
| 2 | 過去分CHAを取得し、918頭に結合 | 段階1 |
| 3 | 併走/単走・先着/遅れ・追切種類の入着率を人気統制つきで測定 | 段階2 |
| 4 | 第1報の「複合指数下位1/3スクリーン」と組み合わせた挙動 | 段階3 |
| 5 | 残余があるかを見て、厩舎話の必要性を再評価 | 段階4 |
