## 版とハッシュの扱い（複製時の注意）

**ハッシュとバイト数の正本は同梱 `SHA256SUMS.txt` の1箇所だけです。** 本文には意図的に書きません。

9/10 に実際に事故が起きています。Obsidian（Google Drive）へ複製した `パンダズCSV引渡し_00_インデックス_20260910.md` は
本文にハッシュ表を持っており、その値が **`218621d` 時点の旧版**（`01` = 9,999 B / `64bcd88b…`、`02` = 14,476 B / `248122c6…`）で
固まったまま、パック側が `d9b3f8f` → `36c15d6` と進んだため**内容と食い違いました**。
さらに同パックの `SHA256SUMS.txt` 自体も `02` の表崩れ修正がSHA再生成の後に入ったため陳腐化し、`sha256sum -c` が FAILED を返す状態でした（`36c15d6` で修正）。

このため次の運用にします。

1. **文書本文にハッシュ・バイト数を書かない**（この 00 も、Obsidian/Drive 版も）。参照は `SHA256SUMS.txt` へのポインタのみ
2. **`SHA256SUMS.txt` は 00〜04 のいずれかを変更したら必ず最後に再生成し、`sha256sum -c` を通す**
3. **Obsidian／Drive 版は「同一内容の複製」ではなく「Git正本への参照を付した別ファイル」**として扱う。
   バイト数が Git 版と異なるのは正常で、**同一性ではなく参照先の正しさを検証する**
4. 文字コードは **CSVはUTF-8 BOM付きに統一**（現状 `03` と受領票CSVはBOM付き、配布アーカイブのルート `MANIFEST.csv` はBOMなし。次回作成時に揃えます）
