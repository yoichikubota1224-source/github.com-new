## 0. 結論

**パックは内部整合しており、引渡し報告の数値はすべて実ファイルから再現できました。** manifest 48件のSHA-256は48/48一致、01_roi.csv の1,222行はすべての報告値と一致します。

そのうえで、**回収率として使うには決定的な障害が1つあります。**

> **購入方式が全1,222行で不明であり、しかも 311行(合算派生行)は「均等購入を前提とした加重平均」で作られています。**
> パンダズ競馬の現行既定は **オッズに反比例した賭け金・固定払戻の意図**(サイトの説明書)です。
> 賭け金がオッズで変わる方式の回収率を、件数nで加重平均しても**プールされた回収率にはなりません**。
> したがって311行は、**方式が均等購入でなければ系統的に誤っている**可能性があります。
> `roi_method=UNKNOWN` は正直なラベルであり、**方式が確定するまで数値として使えません**。

もう1点、**当方が9/8に算出した回収率との比較可否**にも影響します。9/8の値は**全頭均等1点購入の理論値**として明示していました。パンダズ由来の468行が均等購入でないなら、**両者は同じ「回収率」という語で呼べません**。混ぜて評価しないでください。

## 3. 【最重要】合算方法の正体と、そこから生じる3つの欠陥

同梱の旧コード `evidence/legacy_code/fill_trainer_sire_roi.py` と `fill_jockey_roi.py` を読み、311行の作り方を確定しました。

```python
def wmean(items):                    # items = [(単回収率, 複回収率, 件数n), ...]
    s1 += 単回 * n ;  s2 += 複回 * n ;  tot += n
    return (round(s1/tot), round(s2/tot), int(tot))
```

**すなわち Σ(ROI_i × n_i) ÷ Σn_i を整数へ丸めた値**です。場集計・距離集計・回り集計・クラス集計の311行はすべてこれで作られています。

### 欠陥1 — この式は「均等購入」を前提にしている

プールされた回収率は **Σ払戻 ÷ Σ賭け金** です。1出走あたりの賭け金が一定(均等購入)なら、これは `Σ(ROI_i × n_i) ÷ Σn_i` に一致します。**しかし賭け金がオッズで変わるなら一致しません。**

サイトの現行既定は **オッズに反比例した賭け金**です。もし元表がその方式なら、**311行の加重平均は正しい回収率ではありません**。方式が確定するまで、**311行を数値として扱えません**。これが指示書 §9 の優先課題①（均等購入と均等払戻の混同防止）②（オッズに反比例した回収率の再集計監査）に対する当方の回答です。

### 欠陥2 — 二重の丸め

元表の掲載値がすでに整数%です。それを加重平均して**もう一度整数へ丸めています**。分母(賭け金総額・払戻総額)が無いため、**元の精度を復元できません**。n が小さい行ほど誤差の影響が大きくなります。

### 欠陥3 — 場・距離・回りの3行は独立な証拠ではない

コードを読むと、**場集計・距離集計・回り集計はいずれも同一のコース別表インデックス `cidx_e` を異なる切り口で絞り込んだもの**です。したがって**同じ出走が複数の行に重複して含まれます**。

実測でも確認しました。3切り口が揃うエンティティ21件で、切り口別の Σn は 19件で一致せず（例：ある騎手で 場Σn=1326 / 距離Σn=1196 / 回りΣn=2117）。これは各行が全域ではなく**特定の値(場=X, 距離=Y, 回り=Z)の部分集合**であることを示します。つまり **3行は「同じ元表の重なり合う部分集合」**です。

→ **「場でも距離でも回りでも高ROI」を3つの確認と読むと、同じ出走を3回数えます。** ガードレールE(卍の二重加点禁止)と指示書 §9 優先課題③（同一データの重複加点防止）に直接該当します。**成果物A の `independence_note` 列にこの注意を全該当行へ書き込みました。**
