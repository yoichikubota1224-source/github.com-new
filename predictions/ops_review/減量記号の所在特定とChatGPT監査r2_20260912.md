## 1. 【最重要】減量記号は「未取得」ではありませんでした

**9/11以降、当方は「出走表33列に減量記号の欄がない」ことを根拠に、ウルトラ／マストバイの減量条件を全件UNKNOWNとし、同一レース同性の斤量分布からの導出を ［推：斤量差］ にとどめていました。ChatGPT監査もこの前提を受け入れていました。**

**実際には JRDB IDM の「斤量」列に記号が同梱されていました。** `53△` `52▲` `53◇` `51★` `54☆` の形式です。同日の指数CSVのうち、タイム指数CSVとスライド競馬新聞CSVの斤量列には記号がなく、**IDM CSVだけが持っていました**。

| 検証 | 結果 |
|---|---|
| 記号を持つ馬 | 308頭中45頭（記号なし263） |
| 記号の種類 | ▲・△・☆・◇・★ の5種 |
| 斤量差との整合 | ▲=3kg(14/18)・△=2kg(6/9)・◇=2kg(7/7)・☆=1kg(7/9) |
| **9/11の推定が誤っていた馬** | **少なくとも14頭**（記号なしで斤量差2〜3kgが9頭／記号ありで差0が5頭） |

**記号列が正本です。** ただし記号→kg数の原典定義は未取得で、★は2頭の斤量差が1.0と4.0に割れています（**人間確認必須**）。

### 是正

`scripts/ledger.py` に `LEDGER_KINRYO` を追加し、減量条件を記号で確定（出所タグ ［実：提供値］）。**記号が未供給のときだけ従来の推定に戻り UNKNOWN になります。** 受入テスト T07 を「記号があれば確定・無ければUNKNOWN（推定で確定しない）」へ書き換え、**22件全PASS** を維持しました。

### 判定の変化

| 項目 | 変化 |
|---|---|
| 条件別台帳のUNKNOWN | **326行 → 128行** |
| 減量条件198行 | **TRUE 160／FALSE 38 で確定** |
| 集約TRUE | **22件 → 26件** |
| 残るUNKNOWN | **4件（すべて語義二義）** |

確定に転じた3頭と、不成立に確定した1頭があります。**9/11監査の A04 と ChatGPT監査の P0-5 のHOLDが解消しました。**

## 2. ChatGPT監査 修正依頼の検証結果

**P0-1〜P1-12 の12項目は全件成立。** うち10項目は当方の実欠陥、2項目は当方が既に遵守しており**ChatGPT側の空振り**でした。同値内訳の食い違いは**ChatGPTが正しく、当方の前回本文が誤り**でした。

|---|---|---|
| P0-1 | はい | 「最高指数」1列の空判定で「タイム7項目全欠」と書いていた。真の全欠は本線7Rで2頭のみ。**原典に全指数欠損一覧という正本リストが同梱されていた** |
| P0-2 | はい | 回収率タグのUNKNOWNを支持系統に数えていた（5頭6件）。支持最多も2頭同数で「単独最多」は誤り |

| P0-4 | はい | 危険区分の本文とCSVが不一致。**本文が標準出力からの手書きで単一出所が無かった** |
| P0-5 | はい | 旧確定台帳と新台帳の版差（31行）を突き合わせていなかった。**版IDと生成時刻も持っていなかった** |

| P1-7 | はい | ラップキャラ空欄を46/108頭に不安計上。**供給側は HOLD と明記済み**で定義は資料内に記載なし |

| P1-12 | **いいえ（空振り）** | 監視馬14頭限定は5箇所で明記済み |

### ChatGPT監査側の誤り 7点

P1-10・P1-12 の空振り／P1-11 の指摘が不完全（展開順位の誤りと符号反転を見落とし）／P1-7 の「不適と断定」という引用が不正確（当方パックに「不適」は0件）／P0-2 の出力集合の変化に未言及／「59騎手」の数え方が曖昧／名寄せ規則が未返却／P0-5 の「条件別証跡が必要」は既に同梱済みで部分的に反証。

### r2 での主な設計変更

支持・不安を**独立バケット**に再設計しました。**従属量（合計値順位）・定義未取得（ラップキャラ空欄）・UNKNOWN（回収率）・ゲート未通過（運勢参考値）は票に数えず、保留枠として理由付きで残します。**
