## 1. 相談の趣旨(利用者指示の記録・2026-09-07)

> 荒れるレースに特化してほしい。障害・新馬・少頭数レースは不要(35レース予想不要)。選定・穴馬抽出したレースに特化して全頭分析をしてほしい。無駄な時間労力削減。そのために、レース後の結果分析、開眼をしていただいている。荒れるレース傾向。14係にて相談依頼。

要求を4点に分解する。

| # | 要求 | 本書での扱い |
|---|---|---|
| A | 障害・新馬・少頭数を対象から外す | §3-2 で閾値の安全域を実測 |
| B | 35R全部の予想は不要 | §3-1 で削減がどこで効くかを実測 |
| C | 選定したレースは**全頭分析** | §3-1・§5 |
| D | 結果分析は**荒れ傾向の学習**のため | §4(ここが最大の制約) |

## 2. 提案する工程(絞り込み後)

```text
Step0  事前除外   障害 / 新馬 / 少頭数        ← 新設。除外理由と除外レース一覧を必ず記録
  ↓
Step1  スクリーニング(機械・残り全レース)     ← 安価。ここは絞らない(理由は§4)
       テクニカル6 → 波乱パターン → 人気馬脆弱性 → 妙味密度
  ↓
Step2  荒れ候補の選定(閾値で決まる。本数ノルマなし・0Rを許容)
  ↓
Step3  全頭分析(選定レースのみ)              ← ここに労力を集中。13視点パネル
  ↓
Step4  穴馬抽出(選定レース内)
  ↓
Step5  結果の収集(絞らない・全レース)         ← §4。荒れ傾向学習の入力
```

**核心**: 削減するのは **Step3(全頭分析)の対象**であって、Step1(スクリーニング)でも Step5(結果収集)でもない。

## 3. 実測(8/16データ・35R/478頭で検証)

### 3-1. 労力削減はどこで効くか

| 工程 | 現行(8/16実績) | 絞り込み後 | 削減 |
|---|---:|---:|---:|
| Step1 スクリーニング | 35R(機械処理) | 28R(機械処理) | 7R(コストはもともと小) |
| **Step3 全頭分析** | **478頭**(全35R・13視点パネル・490エージェント出力) | **72頭**(選定5R) | **85%** |

→ **要求Bの実体は Step3 にある。** 478頭→72頭で85%減。Step1を削っても削減幅は小さく、代わりに§4の副作用が出る。

### 3-2. 除外条件の安全性 ― 少頭数の閾値に危険域がある

「少頭数」の閾値を変えたとき、**8/16に実際に選定された5Rを巻き添えで落とすか**を全域で確認した。

| 除外閾値 | 除外レース数 | 選定5Rの巻き添え |
|---|---:|---|
| 8頭未満 | 1R | — |
| 9頭未満 | 3R | — |
| 10頭未満 | 4R | — |
| **11頭未満** | 5R | **— ← 安全域の上限** |
| **12頭未満** | 6R | **札幌8R(11頭)を除外** |
| 13頭未満 | 11R | 札幌8R |
| 14頭未満 | 15R | 札幌8R |

**札幌8R(11頭)は、8/16で唯一の CHAOS_A(最上位の荒れ候補)であり、穴軸再判定候補を含むレースだった。** 「少頭数は不要」を12頭未満で実装すると、その週の最有力候補を機械的に捨てる。

- **新馬の除外は安全**: 4R除外・巻き添えなし。
- **障害は既に対象外**: 8/16は新潟9R(障害)を最初から除外済み。現行どおりでよい。
- **推奨案(裁定事項)**: 事前除外 = 障害 / 新馬 / **10頭未満**。この組み合わせで 35R→28R、除外7R、**選定5Rは全て残存**。失う波乱側レースは新潟11R(P2・妙味0頭=どのみちREJECT)1件のみ。

> 少頭数を外したい本来の理由(荒れにくい・妙味が立ちにくい)は理解できるが、**8/16のデータでは11頭のレースが最上位の荒れ候補だった**。閾値は「頭数」単独ではなく「頭数 × 波乱パターン」で持つ案も§5に置く。

### 3-3. 事前除外の記録

除外は母集団を変える操作なので、**除外した事実が残らないと後から母集団の比較ができない**。

- 除外レース一覧(racekey・レース名・頭数・除外理由コード)を毎週の成果物に含める。
- 除外理由コードは `EXCLUDED_JUMP` / `EXCLUDED_NEWCOMER` / `EXCLUDED_SMALL_FIELD(n)` の3種を提案。
- 除外レースはスクリーニングの分母から外すが、**§4の結果収集からは外さない**。

## 4. 【最重要】荒れ傾向の学習と、予想の絞り込みは別 ― 対照群の問題

要求Dは「レース後の結果分析で荒れるレース傾向をつかむ」。これは §1 の評価軸(結果で方法を評価しない)とは**別の活動**である。両者を分けて扱いたい。

| | 目的 | 結果の使い方 |
|---|---|---|
| 方法の評価 | 規約どおり動いたか・記録が残るか | **使わない** |
| **荒れ傾向の学習** | どんな条件のレースが実際に荒れるか | **使う**(研究・SHADOW) |

**傾向を学ぶには、荒れたレースだけでなく「荒れなかったレース」も要る。** 選ばれた5Rの結果だけを集めても、選定条件が荒れを弁別できているかは測れない。予想の母集団を絞ることと、学習の母集団を絞ることは分ける必要がある。

**現状の最大のボトルネック**: 8/16の結果データは **35R中1R分しか存在しない**(札幌記念の `.rtd` 1本のみ。他34Rの払戻ファイルは全て0バイト。本環境はJRA/netkeibaへegress遮断)。この状態では荒れ傾向の学習は着手できない。

→ **相談事項**: 予想は絞る一方で、**結果は事前除外レースも含めた全レース分**を収集する運用にできるか。必要なのは `racekey, 馬番, 着順, 人気, 単勝, 複勝` + 3連系払戻の1枚のCSVで足りる(07_結果分析 第2部の受領仕様と同じ)。

## 8. 裁定の反映と再計測(2026-09-07)

### 8-4. 指数と結果は別 ― 唯一残る未裁定事項

「指数はCodexが全レース抽出」により、**対照群の指数側は確保された**。一方、荒れ傾向の学習に要るのは **結果(着順・人気・払戻)** であり、こちらは依然として **35R中1R分しか存在しない**(§4)。

- 指数(発走前) = Codexが全レース抽出 → **解決**
- 結果(発走後) = 収集経路が未定義 → **未解決**

必要なのは `racekey, 馬番, 着順, 人気, 単勝, 複勝` + 3連系払戻のCSV1枚(07_結果分析 第2部の受領仕様と同一)。**予想は絞っても、結果は事前除外レースを含む全レース分**でないと、荒れ傾向の弁別力を測れない。
