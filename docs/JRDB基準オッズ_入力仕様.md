---

## 0. これは何か

依頼書v1.0の解析エンジンは**実装・検証済み**である。データが届けば即座に走る。
本書は、Codex側の抽出出力が満たすべき**列名・形式・主キー**を定めたもの。
ここに合わせて出力していただければ、変換なしで通る。

実行:

```bash
python3 scripts/kijun_odds.py \
  --kijun   基準オッズ.csv \
  --now     現在オッズ.csv \
  --de      DE出走表.csv \
  --ability 能力統合.csv \
  --out     reports/kijun
```

`--de` と `--ability` は省略可。省略した場合、該当項目は `[不足]` として保持し、
能力ゲートは全馬 `HOLD_MISSING` になる(0や推測で埋めない)。

## 1. 主キー

```text
対象日 + racekey + 馬番
```

**馬名だけの結合は行わない。** 馬名は一致検査にのみ使う(不一致は `WARN` として全スナップショットを走査)。

| 列 | 形式 | 例 |
|---|---|---|
| `対象日` | `YYYY-MM-DD` | `2026-08-29` |
| `racekey` | 8桁(場2+年2+回1+日1+R2) | `07263208` |
| `馬番` | 整数 | `11` |

---

## 2. ファイル1: 基準オッズCSV(必須)

| 列 | 必須 | 内容 |
|---|---|---|
| `対象日` `racekey` `馬番` | ● | 主キー |
| `馬名` | ● | 一致検査用 |
| `基準単勝` | ● | JRDB基準単勝オッズ |
| `基準複勝` | △ | 単一値の場合はこちら |
| `基準複勝下限` `基準複勝上限` | △ | 範囲の場合はこちら。両方あれば中央値を採る |
| `基準単勝順位` | 任意 | 無ければ `基準単勝` から昇順で導出する |

⚠ **`基準複勝` と `基準複勝下限/上限` はどちらか一方があればよい。** 両方無い場合は `[不足]`。

## 3. ファイル2: 現在オッズCSV(必須・時系列可)

| 列 | 必須 | 内容 |
|---|---|---|
| `対象日` `racekey` `馬番` | ● | 主キー |
| `取得時刻` | ● | **ISO8601・タイムゾーン付き** `2026-08-29T11:30:00+09:00` |
| `現在単勝` | ● | |
| `現在複勝下限` `現在複勝上限` | ● | 複勝は必ず範囲で |
| `馬名` | 任意 | 一致検査用 |

**1頭につき複数行(スナップショット)を入れてよい。** `取得時刻` の昇順で並べ、
最新を「現在」、その1つ前を「前回」として `前回比` を計算する。
スナップショットが1本しかない場合、`前回比` は `[不足]`。

## 4. ファイル3: DE出走表CSV(任意だが強く推奨)

| 列 | 内容 |
|---|---|
| `対象日` `racekey` `馬番` `馬名` | 主キーと照合 |
| `状態` | `出走` / `取消` / `除外` / `中止` |

⚠ **取消・除外・中止は解析対象から分離する。** 無い場合、頭数一致検査と分離が `[不足]` になる。

## 5. ファイル4: 能力統合CSV(任意)

| 列 | 内容 |
|---|---|
| `対象日` `racekey` `馬番` | 主キー |
| `統合能力順位` | ARM-B の判定に使う |
| `IDM順位` `タイム指数順位` `STRIDE総合順位` | ARM-C の判定に使う |
| `運勢` `ROI` `展開` `調教` | 出力表Cへそのまま載せる文字列 |

**無い場合、能力ゲートは全馬 `HOLD_MISSING`** になる。§6の3アームが機能しないため、
基準オッズだけで穴馬を昇格させないという規約上、**候補は1頭も出ない。**

---

## 6. 欠損の扱い(依頼書§2・§11)

- `0` / 空欄 / `-` / `--` / 非数値 は **すべて `[不足]`** として保持する
- **`[不足]` を 0・平均・推測・消し・断念へ変換しない**
- 比率の一方が `[不足]` なら比率も `[不足]`。分類は `HOLD`、仕分けは `HOLD_MISSING`

## 7. 文字コード・原本

- UTF-8(BOM可)/ CP932 のいずれでも可。**厳密復号し、`errors="replace"` は使わない**
- **原本CSVは一切変更しない**(読み取り専用)

## 8. ⚠ 仕様上、確認いただきたい点 4件

依頼書v1.0で定義が一意に定まらなかった箇所。**当方の暫定実装を記すので、違う場合はご指示ください。**

### (1) `基準複勝` は単一値か範囲か

JRDBの基準複勝が範囲で提供されるのか点で提供されるのか、当方では確認できていない。
暫定: **両方受け付ける。** 範囲なら中央値、点ならその値を分母にする。

### (2) 基準比がちょうど `1.00` のとき

依頼書は「1.00を上回る=基準より高い / 下回る=基準より売れている」とあるが、**`==1.00` の定義が無い**。
暫定: **`1.00` は「基準より低い」側に含めている。**
⚠ この結果、価格が基準どおりの馬が「価格だけの穴」と仕分けられる。
`基準どおり` という中立の判定語を §8 の語彙へ追加されるほうが自然だと考える。

### (3) ARM-B / ARM-C の「レース上位5頭以内」

出走頭数は7〜18頭と幅がある。**7頭立ての上位5頭(71%)と18頭立ての上位5頭(28%)は意味が違う。**
暫定: **依頼書どおり固定で上位5頭**としている。頭数比(例: 上位1/3)へ変える場合はご指示を。

### (4) `現在単勝人気順位` は提供されるか

暫定: **提供が無ければ `現在単勝` の昇順から導出する。** 同着オッズは先着順位。
確定人気は事前分析へ混入させない(§11)ため、事後検証まで一切参照しない。

## 9. 市場乖離度の暫定基準(§9)

依頼書は「高／中／低」の閾値を定めていないため、当方で操作的に定義した。
**これは規約への昇格ではない(`RULE_PROMOTION=NONE`)。人間確認事項である。**

| 判定 | 条件 |
|---|---|
| 高 | 基準順位相関 < 0.60 **または** 3段階以上変動が `max(3, 頭数÷4)` 頭以上 |
| 中 | 相関 < 0.85 **または** 3段階以上変動が2頭以上 |
| 低 | 上記以外 |

⚠ **市場乖離度は波乱確定を意味しない。** コンピ波乱構造とは別列である。

## 10. 検証状況

実データ未着のため、**既知の答えを持つ合成データ**で通した。

| 仕込んだ欠陥 | 検出 |
|---|---|

| 大幅上昇馬(基準比2.60・能力ARM_C PASS) | `能力確認済み過小評価候補` |
