# 週次調教CSVの取り込み手順(ランブック)

`目的: 調教データを毎週ためて、補正後zの検定を決着させる` / `PURCHASE_ALLOWED=NO`

第5報(`predictions/20260823/18_…`)で、日×場×コースの馬場差ベースラインを自前で作れば
終い1Fが情報を持つことが分かった(補正前 p=0.8037 → 補正後 p=0.0996)。
**あと必要なのは標本だけ**である。この手順はその標本を毎週ためるためのもの。

---

## 1. 羊一様にお願いする作業(週1回・数分)

**いつ**: 金曜〜土曜、その週の調教が終わったあと(いつも通りのタイミングで結構です)

**なにを**: いつも保存されている次の2本を、いつものDriveフォルダへ入れる

| ファイル | 中身 |
|---|---|
| `坂路<期間>.csv` | その週に坂路で追い切った全馬のハロン別ラップ |
| `ウッド<期間>.csv` | その週にウッドで追い切った全馬のハロン別ラップ |

保存先フォルダ: `1LjvYf_Eajp0bwqOZnvlD-KkvNGdYU0fY`(これまでと同じ場所)

**ファイル名は自由**です。取り込み側は**中身を見て**坂路/ウッドを判定し、日付も中身から読みます。
期間が前週と重なっていても構いません(行単位で重複排除します)。

### ⚠ ただし1点だけ

**坂路のファイルをウッドの名前で保存してしまう事故が実際に起きています。**

2026年8月1日〜7日週で、`ウッド8.1－8.7..csv` として保存されたファイルが
`坂路8.1－8.7.csv` と**バイト完全一致**でした。結果としてこの週のウッドが存在せず、
**8/8・8/9の2開催日(934頭)が分析に使えなくなっています。**

取り込みスクリプトはこの不一致を検出して警告しますが、**元データは復元できません**。
保存時に、ウッドのファイルが40列(ヘッダが「場所,コース,回り,年月日,…」で始まる)に
なっているかだけご確認ください。

## 2. 自動で走る処理(Routine)

`trig_01GUM3eQx9r5K7wM6JsWrLWR` / 毎週 **月曜 09:00 JST**(cron `0 0 * * 1` UTC)/ 通知: プッシュ+メール

毎週やること:

1. リポジトリを更新し、`data/chokyo/coverage.json` で先週からの増減を確認
2. `chokyo_baseline.py` → `chokyo_rejoin.py` → `chokyo_probe.py` を再実行
3. 差分があればコミット・プッシュ
4. **今週のCSV保存のお願い**と、現在の到達度(収録日数・p値・必要標本までの残り)を通知

### ⚠ Routineは自分でDriveから取ってくることが「できません」

Routineが起動するセッションには **Google Drive のコネクタが付きません**。
当セッションからRoutineにコネクタを引き継ぐことができないためです([実]: 作成時に
`this trigger stores no MCP connectors` の警告が返っている)。

したがって毎週の流れはこうなります。

```
羊一様: CSVをDriveへ保存
   ↓
Routine(月曜09:00): 「今週のCSVを入れてください」と通知 + リポジトリ側だけ再検定
   ↓
羊一様: Claudeに「調教CSV取り込み依頼」と送る
   ↓
Claude(通常セッション・Drive接続あり): Driveから取得 → 取り込み → 再検定 → プッシュ
```

**取り込みのきっかけだけは、羊一様からの一言が必要です。**

### 完全自動にしたい場合

claude.ai の Routines 画面から**同じ内容のRoutineを作り直す**と、Google Drive コネクタを
付けられます。付いていれば、Routineが自分でDriveを見に行って取り込みまで完結します。
当方からはコネクタを付けられないため、この操作だけは羊一様にお願いすることになります。

## 3. 手動で取り込む場合

```bash
# Driveから落としたCSVを一時ディレクトリに置いてから
python3 scripts/chokyo_ingest.py --src /path/to/csvs

# 正規化レイアウトへ取り込まれる
#   data/chokyo/hanro/YYYYMMDD.csv   … 坂路(ヘッダ無し18列・CP932)
#   data/chokyo/wood/YYYYMMDD.csv    … ウッド(ヘッダ有り40列・CP932)
#   data/chokyo/coverage.json        … 収録日と欠落の一覧

# 再分析
python3 scripts/chokyo_baseline.py    # 日×場×コースのベースライン → z化
python3 scripts/chokyo_rejoin.py      # 確定結果に結合して再検定
python3 scripts/chokyo_probe.py       # 人気交絡とカバレッジの点検
```

`chokyo_ingest.py` は**冪等**です。同じものを何度取り込んでも結果は変わりません。

## 4. いまどこまで来ているか

| | 値 |
|---|---|
| 補正後zの検定(第5報時点) | 3着内率 28.5% vs 21.1% / **p=0.0996**(有意水準未達) |
| 必要標本(検出力80%・両側5%) | **1群あたり n≈534** |
| 第5報の標本 | 1群 179〜213頭 |
| バックログ取り込み後の見込み | 1群 **約387頭** |
| **8/1〜8/7週のウッドが復元できた場合** | 1群 **約588頭** → **必要標本を満たす** |

**つまり、失われた1週分のウッドが戻れば、この検定は決着します。**

## 5. さらに良い選択肢(未取得)

Drive に、週次CSVより**はるかに良い**アーカイブが2本あることが分かりました。

| ファイル | サイズ | 収録 |
|---|---:|---|
| `hc_hanro_training_20260103-20260808.csv` | 28.7 MB | 坂路 2026-01-03〜08-08 |
| `wc_wood_training_20260103-20260808.csv` | 12.9 MB | ウッド 同上 |

週次CSVに対する優位点:

- **7か月分**が1本にまとまっている(週次CSVは5/12〜8/22で、しかも5/17〜6/20が33日欠けている)
- **血統登録番号を持っている**。現在の結合は**馬名の文字列一致**に頼っており、
  同名馬・表記ゆれで取りこぼす。血統登録番号なら確実に結合できる
- JV-Data由来の正規化スキーマ(`record_type, train_date, train_time, ketto_toroku_bango,
  f4_total, lap_4_3, f3_total, lap_3_2, f2_total, lap_2_1, f1_total, consistency, …`)で、
  `consistency` に OK/NG の自己検査フラグまで入っている
- **8/1〜8/7週のウッドを含む**。§1の事故で失われた分がここにある

⚠ **どちらもDrive MCPの10MBダウンロード上限を超えており、当方から取得できません。**
ご対応いただけるなら、次のいずれかで取り込めます。

1. 月ごと等に分割して10MB未満にし、Driveへ置く(推奨。`wc_wood` は2分割で足ります)
2. 直近3か月など、必要な期間だけ書き出す

取り込めれば、結合キーを馬名から血統登録番号へ移行し、第5報の全数値を作り直します。

## 6. 統治

```text
ANALYSIS_SCOPE   ：POST_RACE_RESEARCH_ONLY
PURCHASE_ALLOWED ：NO
RULE_PROMOTION   ：NONE
[不足]の扱い     ：8/1〜8/7週のウッド、収録外コース、大容量アーカイブ2本を
                   0や「なし」に変換していない
```

本手順はデータ取り込みの運用であり、印・買い目・点数・資金配分・購入判断を含まない。
